# 墙网人工复核界面：未闭合清单驱动的逐项处置

本项是 Issue #32 的界面与交互实现，依赖 PR #33 的模型层处置 API。界面不实现新的拟合或成房算法；所有处置都调用 `applyReviewAction`，房间与未闭合清单仍由模型层按墙网几何重算。

## 操作步骤

1. 导入点云并进入「建筑模型」，生成候选后切换到「平面编辑」。
2. 右侧「墙体与房间复核」按原因与缺口大小列出未闭合项，显示位置、涉及墙段与处置状态；分组来自模型字段，不写死样本墙段编号、计数或坐标。
3. 点击清单项，画布高亮缺口并缩放到该区域；再次点击或取消绘制可恢复整层视图。
4. 选中项后可逐项处置：
   - **连接两端**：确认式操作，端点按模型层既有吸附口径连接；
   - **补墙**：在画布点两点，第二点移动时显示吸附预览，提交后记录人工来源；
   - **删伪影**：在画布选中墙段，填写原因后软删除，保留留痕；
   - **确认洞口**：确认式操作，不再计入未闭合，但不据此生成房间。
5. 每次处置后，清单、房间数、房间列表与处置记录即时刷新；「撤销模型编辑 / 重做模型编辑」沿用应用原有模型历史。
6. 处置随工程保存，重开后恢复。未进入复核的正常自动流程没有新增步骤或弹窗。

## 点云不可用时打开工程

按负责人决定：工程已含建筑模型时，即使点云文件缺失或无法读取，也保留建筑模型、复核记录与处置历史并允许打开。

- 工程标题与建筑模型工作区常驻标明「点云对照不可用」；
- 「从点云生成建筑候选」「点云对照」「墙面门窗识别」停用并说明原因；
- 仍可依据已保存的墙网模型与未闭合清单做人工处置；
- 点云恢复后重新打开同一工程即恢复对照，不迁移工程文件。

## 验证

合成夹具由 `scripts/wall-review-fixture.ts` 生成：8×6 m 房间，东墙 0.6 m 缺口，室外一处孤立伪影墙段。单元测试另外把同一份点云送入真实 `fitWallLines`，验证得到 6 段墙、0 房间及一处 0.6 m 缺口。

```sh
# 根目录与 windows-studio 分别安装依赖后，在 windows-studio/ 下：
npx vite-node scripts/wall-review-fixture.ts
npm test
npm run build
npm run test:ui
```

- `tests/wall-review-ui.test.ts`：清单/分组与入口、补墙成房、连接、删伪影、确认洞口、撤销、保存重开，以及点云不可用/恢复的工程语义。
- `tests/wall-review-ui.spec.ts`：真实浏览器点击与文件选择流程；画布定位、两点吸附预览、房间计数更新、撤销/重做、保存重开、连接、删伪影与重拟合阻断。
- 既有「点云缺失即拒绝打开」断言：没有现成断言需要修改；新增用例覆盖新语义。已有工程在点云可读取时仍走原有恢复路径。
