# Blender 物体创作方案：调研与综合考评

调研日期：2026-09-07。范围：网络一手资料、当前源码和已安装 Three.js 导出器的只读核对。没有执行重建、安装 Blender、修改应用代码或重新打包。

本文中的「已确认」指文档或源码事实；「建议」指工程判断；性能、重建质量和 Blender 往返保真仍需样本验证，本文不提供伪装成实测的分数或时延。

## 1. 建议决策

推进「物体创作台」，以**可靠选取物体 → 生成可检查的表面 → 切换创作材质 → GLB 导出**为主线。Blender 是继续编辑的出口，普通用户在应用内就应完成第一件作品。

第一优先级是对象提取的数据正确性。第二优先级是受限场景的表面重建与材质预览。第三优先级是 Blender 实际导入验收。单独增加导出按钮不足以完成这条体验。

首版建议接受：扫描较充分、静止、轮廓明确的普通物体；允许保留缺口并查看原始点。薄椅腿、玻璃、镜面、植被以及与背景紧密相连的对象作为困难样本，不预先承诺通用成功。

## 2. 当前工程的关键发现

| 已确认事实 | 源码位置 | 对方案的影响 |
| --- | --- | --- |
| PointCloudData 有 XYZ、RGB、强度、可见性，没有网格面、法线、UV 或材质 | `src/domain/types.ts:26` | 需要独立模型资产；不能把现有点云改名为网格 |
| PLY 导出只写顶点与 RGB，没有 face 元素 | `src/domain/ply.ts:63` | 可保存扫描点，不自动产生实体表面 |
| 框选遍历 renderedPositions / visibleOriginalIndices | `src/components/PointCloudCanvas.tsx:177` | 目前选的是渲染样本，不是完整源数据中的物体 |
| 普通桌面渲染上限 60 万点，窄屏 25 万点，CAD 模式 12 万点 | `src/components/PointCloudCanvas.tsx:413` | 不同显示预算不能改变最终提取物体的精度或范围 |
| PCD 导入上限：Capacitor 原生端 100 万点，其他端 400 万点 | `src/platform/files.ts:9`、`src/App.tsx:411` | 超限时导入阶段已经采样，后续仅遍历内存点也不能恢复全量 |
| PCD 解析器内部使用原始采样索引，但返回对象未保留该索引表 | `src/domain/pcd.ts:174`、`:263` | 需要可追溯的源文件点索引或可重放的空间选区 |
| 桌面打开文件只返回文件名和字节，不返回可重读的资产标识 | `electron/main.cjs:24` | 精细提取需要保留受控源引用或导入快照；文件变动要识别 |
| 现有 3DGS 功能校验并打包 COLMAP 输入，不训练高斯、不生成网格 | `src/export/threeDgs.ts:16`、`:39` | 不应把已有 3DGS 导出菜单当作现成重建引擎 |

上述导入点数限制在已检查调用链中明确用于 PCD，不据此推断 PLY、LAS 等格式均有相同上限。

建议修正数据链：屏幕选区只用于快速预览；保存对象前，将选区的视角、范围和深度约束应用到完整可用的源数据。全量数据不可用时明确显示「来自采样数据」，提供重新读取原文件的路径。原始点索引必须绑定源数据版本，不能只存会随导入改变的数组下标。

## 3. 四种成果应明确区分

| 成果 | 用户获得什么 | 能否满足材质创作 |
| --- | --- | --- |
| 扫描原貌 | 独立点云、位置、颜色、来源记忆 | 可做点的颜色表达，尚无连续表面的光照反应 |
| 表面模型 | 有三角面与法线的独立网格 | 是，适合基础物理材质与 Blender 后续编辑 |
| 粒子／体素雕塑 | 对采集数据进行显式艺术化表达 | 可以，但材质作用于人工生成的粒子或方块表面 |
| 影像式回忆 | Gaussian Splat 等偏重视角外观的表示 | 普通 splat 的外观编辑不等于标准网格材质编辑 |

Polycam 官方 Object Mode 将摄影测量网格和 Gaussian Splats 分成不同重建方式，其 API 也要求网格格式导出具备 mesh 数据。可借鉴的是按「想得到的成果」组织入口，而不是把不同表示藏在同一按钮后面。[Object Mode](https://learn.poly.cam/hc/en-us/articles/27425185907348-How-to-Use-Object-Mode)、[导出能力条件](https://poly.cam/docs/api)。

Scaniverse 原支持页目前转向 Niantic Spatial Capture，当前官方说明同时讨论 meshes 与 splats，并强调结果依赖采集与处理流程。本方案不采用旧页面的格式清单推断当前所有产品能力，也不照搬厂商宣传的速度或精度。[当前官方页面](https://www.nianticspatial.com/products/capture)。

## 4. 重建路线考评

以下为结合当前 XYZ+RGB 输入所作的定性判断，不是算法跑分。

| 路线 | 输入前提与收益 | 主要风险 | 本项目判断 |
| --- | --- | --- | --- |
| 独立 PLY 点云 | 现有数据即可保留扫描信息 | 没有表面，不能完成预期的材质建模体验 | 作为对象原始资产和失败保留项 |
| Ball Pivoting（BPA） | 需要较可靠的法线、合适的半径与采样；从点构造面 | 密度不均、噪点、薄结构影响结果；可留下缺口 | 与 Poisson 并列做首轮候选，以样本决定默认 |
| Screened Poisson | 使用有向法线求连续表面；适合较充分的扫描 | 可能向稀疏或无点处延伸，平滑掉细节或产生多余面 | 候选路线，必须检查低支持区域，不能默认宣称完整 |
| 体素／粒子网格 | 可从现有点云得到可观看的创作形体 | 方块尺寸会改变外形；粒子数量影响面数与文件大小 | 可独立设计为艺术模式，不静默替代重建 |
| 摄影测量 | 多视角图像与相机几何，可重建带贴图网格 | 当前只导入 PCD 的工程缺少必要图像链；难材质仍困难 | 作为有原始照片时的后续支线 |
| 3DGS → 网格 | 需额外的高斯训练、表面约束或网格提取流程 | 输入、算力、几何可靠性和材质解耦都更复杂 | 不列为当前 PCD 首版默认路线 |

Open3D 官方介绍了 BPA、Poisson 和法线估计，并明确指出 Poisson 会向低点密度区域甚至观测外延伸。由此提出的产品要求是：让用户能对照扫描点检查重建结果，而不是把算法输出的闭合表面视作真实完整性。[Open3D 表面重建](https://www.open3d.org/docs/release/tutorial/geometry/surface_reconstruction.html)。

摄影测量与高斯转网格确实存在成熟研究和工具链：COLMAP 的流程从图像建立相机与场景几何，SuGaR 在高斯表示之上增加表面约束和网格提取，并提供 Blender 相关工作流。这里将它们列为后续路线，是因为当前静态 PCD 入口没有同等输入与已验证管线，不是认定高斯永远不能生成网格。[COLMAP 教程](https://colmap.github.io/tutorial.html)、[SuGaR 作者实现](https://github.com/Anttwo/SuGaR)。

处理链建议：非有限点检查 → 保守的重复点／散点处理 → 法线估计与方向处理 → 候选重建 → 检查退化面、异常连接和低支持面 → 必要的轻量化 → 带距离约束的颜色转移。保留原始对象快照；不要用一套全局去噪阈值自动删除细杆或边缘。

模型与点的距离小，只能说明与现有样本较一致，不能证明没扫到的部分真实存在。双向距离、边界和连通性应联合查看；静态 PCD 通常缺少视角覆盖信息，不宜计算一个看似确定的「完整度百分比」。

## 5. Blender 与导出格式

| 方案 | 价值 | 代价与边界 | 建议 |
| --- | --- | --- | --- |
| GLB / glTF 2.0 | 可带网格、法线、颜色及标准材质；GLB 便于单文件交付 | 不承载任意 Blender 节点网络，导出器与导入器必须共同支持所用扩展 | 首版主交付格式 |
| PLY | 适合保留点和顶点颜色；格式本身也可以存网格 | 当前应用写出的 PLY 无面；通常不承载完整 PBR 材质 | 原始资产附件 |
| OBJ + MTL | 常见网格交换方式 | 材质表达和贴图携带较分散，PBR 往返不宜作为默认承诺 | 有实际兼容需求再增加 |
| 原生 .blend | 可保留 Blender 场景和其专属能力 | 需要 Blender 生成链、版本与打包验证 | 后续可选「另存 Blender 工程」 |

Blender 4.5 LTS 可作为固定验收基线；另选实际目标的新版本复查，不用浮动的 latest 代替版本约定。[4.5 LTS 发布页](https://www.blender.org/download/releases/4-5/)、[4.5 导入导出变更](https://developer.blender.org/docs/release_notes/4.5/pipeline_assets_io/)。

本机 Three.js 已包含 GLTFExporter，无需仅为写 GLB 引入新全局依赖；`binary: true` 选择 GLB。该能力解决序列化，不解决选区、重建、UV 或 Blender 往返验收。[Three.js 官方导出器](https://threejs.org/docs/pages/GLTFExporter.html)。

### 材质一致性的具体约束

1. 首批预设建议是「采集原色 / 石膏 / 金属 / 陶瓷」，优先使用基础 metalness/roughness 材质。没有真实 RGB 时标记为无采集颜色，不把渲染占位色称为原色。
2. 原色可能带有采集时的光照与阴影，不能直接宣称它是真实表面反射率。原貌对照可以采用不受新灯光影响的显示；创作材质使用新的光照，两个模式明确标记。
3. 当前导出器 `GLTFExporter.js:1896` 将 `geometry.color` 写作 `COLOR_0`，`:1911` 后遍历属性时没有依赖 `material.vertexColors` 进行剔除。glTF 顶点色会与材质底色相乘。因此纯色金属导出应在**导出副本**中移除或中和顶点色，原始颜色资产不改动。这是基于源码与规范的兼容性风险判断，尚未进行 Blender 实测。
4. glTF 的坐标约定是右手系、Y 向上，长度单位为米；应用使用 Z 向上的观察约定。需明确一次性的坐标转换、单位与原空间变换，防止模型倒置或放大一千倍。输入单位不确定时先让用户核对物体尺寸。
5. `COLOR_0` 按线性值使用；采集 RGB 的编码约定需要明确。灯光、环境和色彩管理也会影响外观，不应承诺跨软件逐像素相同。[glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)。
6. 本地导出器确有 `KHR_materials_anisotropy` 实现，但这不自动证明完整拉丝效果往返一致。复杂纹理、切线、各向异性和程序材质应逐项验证；首版不以其为必要条件。
7. 当前 Three.js 文档把 `KHR_materials_variants` 列为外部插件支持。应用内可保存多种外观，首版 GLB 导出当前选定外观；不要默认承诺一个文件在所有接收端都有材质切换器。[导出器扩展说明](https://threejs.org/docs/pages/GLTFExporter.html)。

**不必把 UV 展开设为基础材质的前置步骤。** 均匀石膏、金属、陶瓷可用基础颜色、金属度和粗糙度标量表达，贴图是可选项；复杂木纹、图案和可携带的纹理贴图再引入 UV／烘焙。这样首版能在可靠网格形成后更快给用户材质反馈。[MeshStandardMaterial 参数](https://threejs.org/docs/pages/MeshStandardMaterial.html)。

## 6. 新手体验：让模型成为一件自己的作品

主路径保持四步：**选一件 → 看清楚 → 换外观 → 保存作品**。第一次进入只展示当前步骤必须的操作。

- 选择：显示「添加／减去」，保留撤销。提供转动查看和深度范围辅助；与墙或桌面连在一起时，允许用户修正自动建议。
- 独立预览：背景淡出而不删除；稳定的物体枢轴、真实尺寸、一键回到原空间位置。实时输入先冻结对象快照，明确该快照的时刻。
- 生成表面：默认先快预览，用户确认后再请求更精细结果。任务状态与取消始终可见；没有可信进度时展示真实阶段，不编造百分比。
- 外观：用同一件物体即时对照不同材质；几何不变就不重新重建。设置重置入口，保存原貌与创作版本。
- 保存：由用户命名，缩略图展示自己的物体。保存来源、处理记录与空间位置；采集时间未知时显示导入时间，不能自行补造记忆信息。
- 退出：恢复进入前的视角与工作状态。沿用右侧悬浮面板语言，物体创作和 CAD 按任务切换，不同时堆放多套编辑器。

「多种素材」分两层：近期为同一对象的材质预设；后续为多个已保存物体的素材库与空间组合。组合阶段再处理摆放、吸附、尺度和对象身份，不让首版一开始就变成完整场景编辑器。

寓教于乐每次只解释一个动作，例如「点记录位置，面连接形体」「形状没变，反光方式变了」。提示可跳过，不设置强制教程或人为成功分数。

模型检查仅显示与下一步有关的提示：是否夹带背景、是否存在需要查看的边界／碎片、是否具备可导出的有效面。表面有边界不一定是错误，可能是物体本身开口；「可导出」只代表格式条件满足，不能当作可打印或工程精度保证。

## 7. 实现位置与成本判断

| 部分 | 建议位置 | 相对投入判断 |
| --- | --- | --- |
| 对象身份、源引用、全量提取与撤销 | 源数据入口、对象资产模块、桌面端受控文件引用 | 中到高；是当前容易低估的工作 |
| 单物体预览与基础材质 | 现有 Three.js 前端能力，按需加载 | 中；依赖已经获得可信网格 |
| 法线与表面重建 | 优先评估本地独立任务进程，保持 UI 响应与可取消 | 高；质量、内存和分发均待验证 |
| GLB 序列化 | 现有 GLTFExporter | 相对低；往返验收仍是独立工作 |
| .blend 自动生成 | 可选外部 Blender 适配 | 中到高；不宜成为所有用户前置依赖 |

以上是工作性质判断，不是人日估算。建议先用固定版本 Open3D 做局部算法验证，再决定最终独立进程的实现和分发方式；不在调研阶段承诺浏览器端一定能承担全量重建，也不为了模型出口将整个 Blender 捆入主安装包。现有桌面壳是 Electron，前端与任务接口应保持清晰边界，本任务不包含框架迁移。

本地独立进程避免把重建任务塞进渲染主线程，但仍需评估源数据传输、工作集内存、取消机制和任务残留。预览、建模、导出使用各自明确的精度等级，并在源数据版本变化后使旧派生模型失效。

## 8. 验证方案与选择门槛

建议先选六类有代表性的真实样本，每种算法使用相同输入与可追溯参数：

| 样本 | 主要观察项 |
| --- | --- |
| 扫描充分的哑光雕塑或箱体 | 轮廓、尺寸、面方向、基础成功路径 |
| 带薄腿或细杆的物体 | 是否断裂、变粗或被去噪删掉 |
| 只有一侧扫描的物体 | 是否产生无依据背面，能否诚实保留缺口 |
| 紧贴桌面／墙面的物体 | 选取是否夹带背景、能否方便修正 |
| 稀疏或密度不均的选区 | 碎片、异常连接、细节与平滑权衡 |
| 无颜色或含非有限坐标的数据 | 原色入口状态、错误说明与失败后资产保留 |

评估分四类，不合成一个掩盖失败的总分：

1. **数据一致性**：提取范围、原始来源、单位、隐藏和编辑语义可追溯；换显示采样预算不改变对象提取结果。
2. **几何适用性**：与观测点的偏差、异常跨接面、连通碎片、边界、薄结构保留；有真实参考尺寸时才讨论几何精度。
3. **交互可用性**：没有建模经验的用户能完成选取、修正、对照、命名和导出；记录耗时、求助次数、失败恢复与操作反馈延迟。
4. **交付一致性**：固定 Blender 版本实际导入 GLB，核对尺寸、方向、枢轴、颜色和各材质；另记生成耗时、峰值内存、面数、文件大小。数字全部来自该样本实测，不引用厂商时间作为本机预算。

先验证至少一个物体的完整链路，再增加材质数量和自动选物。若重建尚不稳定，继续提供对象原貌收藏，并将表面生成标记为试验能力；不要用看起来完整的生成模型掩盖采集信息不足。

## 9. 本轮结论边界

已形成可执行的设计与考评路径；尚未获得真实物体重建样本的运行结果，也未验证 Blender 导入、材质保真、速度或安装包成本。应用源码与现有 AppImage 未因本次调研发生改动。
