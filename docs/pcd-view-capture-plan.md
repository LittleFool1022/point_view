## 当前源码事实

`static_pcd_recorder.py` 的 `image_callback` / `pose_callback` 只缓存消息；生产 precolored 模式还可能不订阅图片。`/cloud_projection/lidar_pose` 是雷达位姿，不能直接当相机光学位姿。

`static_pcd_recorder.py::load_loop_corrected_clouds` 使用：

```text
C(t) = T_corrected(t_nearest) × inverse(T_raw(t_nearest))
T_export_lidar(t) = C(t) × T_raw_lidar(t)
T_export_camera(t) = T_export_lidar(t) × inverse(T_camera_lidar)
```

相机轨迹必须绑定同一次 PCD 导出的轨迹快照、最近邻规则与时间偏差，不能在另一时刻单独读取 corrected_path。`pose_space=raw` 只允许归档/查看；`pcd_export` 也是生产者声明，必须通过实图投影核验后才能开贴图。

`production_fast_livo.sh::save_pcd` 当前只同步 `tri_true_color_*.pcd`。本次用户明确提出附带视角图片，允许在这一目标内设计小型附件；SQLite、rosbag、完整 session 仍不纳入同步。

## 选帧模型

先在 IMU 坐标系计算去偏置的角速度；加速度必须由可靠姿态和重力方向去重力，不能逐轴直接减 9.81，也不能将 `norm(a)-g` 当作完整三轴动态加速度。

在线适配层拟采用曝光结束前约 100 ms 的有效 IMU 窗口。每轴对动态加速度与角速度计算 RMS；保留窗口起止、样本数、最大间隙及偏置估计来源。Livox 加速度单位需根据当前驱动发布实现核实，禁止未核对就把 g 当作 m/s²。没有可靠姿态、IMU 断流或时间失配时拒绝本张附件，不影响点云融合。

```text
M = sqrt(sum_i((a_rms_i / a0)^2) + sum_i((w_rms_i / w0)^2))
Δt = max(Δt_min, Δt_max / (1 + M))
```

起始参数为 `a0=0.3 m/s²`、`w0=0.15 rad/s`、`Δt_min=0.25 s`、`Δt_max=2 s`。反比例间隔只用于近邻重访的质量探测；真正新位姿只受 0.25 s 硬最小间隔限制，避免低加速度匀速运动被 2 s 长间隔漏采。这些是待实测调优的初值，不是设备标定结论。实现使用时间戳，不假设固定帧率。

选帧流程：

1. 时间戳、相机位姿、IMU 有效；位姿/IMU 与曝光对齐偏差各不超过 20 ms。
2. 解码前检查位姿与时间。新位姿采用硬最小间隔；“平移 < 8 cm 且转角 < 8°”范围内的重访采用反比例间隔。四元数 q 与 -q 等价。
3. 只解码候选图，Laplacian 方差不得低于 30。极近位姿视为同一观察位置；两倍位姿阈值范围内再用 8×8 灰度差 < 0.025 判断局部相似；不在远处或大角度视角之间做全局图像去重。
4. 对同一局部视角，只有清晰度同时达到原帧的 1.2 倍且增加至少 5，才进行质量替换；文件数量不增长。比较对象为匹配邻域内最高清晰度，替换最近的旧视角。
5. 用 0.4 m 空间格与 30° 光学观察方向分桶，每桶默认最多 8 张。单桶满时只接受更好的替代帧；全局满时允许从更拥挤的桶借一个名额，优先替换其中较差且足以释放字节容量的图片。预算换入不删除仅有一个视角的桶。
6. 每次会话最多 512 张，单图最多 16 MiB、合计最多 256 MiB。写新副本成功后再移除本次输出中被替换的旧副本、提交保存基准；原始输入图片不删除。为替换暂存允许额外至多一张图片的磁盘空间。没有合适名额时跳过该帧，继续观察后续候选，不能在满额处直接退出。

静止不会因为等待了两秒就累计重复图片，但允许更清晰的一张替换旧图；轻微移动相对已保存位姿累计。匀速平移不依赖加速度触发。快速运动时模糊图片仍拒绝。原地大幅转动可提供纹理观察，但不能据此宣称有多视角几何基线。

灰度描述子、Laplacian 清晰度和覆盖桶均为低成本近似，不能证明纹理可用性或物体表面覆盖率；噪声也可能提高 Laplacian 方差。相似包装的远处/大角度视角不再因图像相似全局误拒绝，但局部弱纹理仍有误拒风险。位姿/时间先门禁、再解码已落实于离线代码；在线有界写队列尚未实现。

明确的策略边界：近邻跨分桶边界时，质量替换会把保留帧重新归桶，桶数量可以变化；不把量化边界两侧的微小位移强行保留为两个独立视角。极近位姿即使图像内容发生变化也不追加照片，当前目标是静态物体扫描。解码探测时钟与保存基准分开：局部写失败不推进保存基准，但即时探测重试仍可能等至下一质量探测间隔，避免失败时逐帧解码。离线构建遇到 I/O 错误会终止并保留未发布目录。

## 本地数据契约

`build_bundle.py` 输入一个 JSON，图片与 PCD 路径均相对 JSON 目录，禁止越界。必需字段：

- `version: 1`、`units: "m"`、非空 `frame_id`。
- `pcd`：唯一 `tri_true_color_*.pcd` 相对路径。
- `pose_space: "raw" | "pcd_export"`。
- `pose_convention: "T_world_camera_optical_xyzw"`。相机光学轴为 x 右、y 下、z 前。
- `imu_acceleration: "gravity_and_bias_removed_mps2"`。
- `calibration`：`model: "opencv_radtan5"`、`width/height`、`intrinsics: [fx,fy,cx,cy]`、`distortion: [k1,k2,p1,p2,k3]`、行主序 16 数的 `T_camera_lidar`。Radtan8 等模型不可删参数硬塞进此版本。
- 可选 `policy`：与 `Policy` 字段一致，默认值见算法段。
- `frames`：每项包含整数 `stamp_ns`、相对 `image` 路径、米制 `position[3]`、单位 `quaternion_xyzw[4]`、去重力加速度 `acceleration_rms[3]`、rad/s 角速度 `angular_velocity_rms[3]`、`sensor_skew_ms[2]`（位姿与 IMU 对齐偏差）。候选输入是适配层产物，不是已有生产清单。

使用现有具备 OpenCV/NumPy 的本地解释器，入口为：

```bash
python3 /mnt/zk/3DGS/scripts/view_capture/build_bundle.py candidates.json output_bundle
```

CLI 参数入口未单独运行；其 `build()` 流程已由本地定向检查调用，无新增依赖。离线工具读取已存在的候选图片，不能减少先前的存储量；在线存储节省依赖之后把 `Keyframes` 放到落盘之前。

输出清单的纳秒时间戳使用字符串，避免 JavaScript 超过 2^53 的精度损失。图片保留原始压缩字节，只有描述子使用缩略图。PCD 与每张图都有哈希；原始标定内嵌在清单中。哈希只证明文件对应，不能证明图片与点云空间对齐。附带 `selection_events`、`coverage_cells`、`image_bytes` 与各图的 `selection_reason/coverage_cell`，便于核对预算和替换行为。

软件入口：原始 PCD 导入 → 创作 → 选取物体 → 采集视角图片 → 选择包含 `capture.views.json` 和 `images` 的附件目录。旧版目录导入组件有本机 Chromium 检查记录；本次作品级附件及工程恢复改动尚未实测，未重新打包或运行 AppImage。原始 PCD 需保留为 sourceBlob，当前打包与校验均限 1 GiB，超过预算需后续流式哈希适配。
