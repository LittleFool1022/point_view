# Point View 物体资产制作台：产品形态、功能与路线图

> 日期：2026-09-08  
> 状态：产品与技术规划，供评审；不代表功能已经实现或验证通过。  
> 核心路线：点云约束尺寸与形体，结构推断辅助成形，原始相机图片提供外观，最终交付可编辑 GLB。  
> 发布边界：OMNI 图片链路尚未上线和实机验证，不放行远程部署与同步。

## 1. 产品目标与职责边界

### 1.1 产品目标

让用户从一次手持扫描中提取一个物体，在本机完成方向和尺寸核对、结构修整、照片贴图及质量检查，得到能继续编辑和复用的三维资产。

第一阶段以纸箱等具有明确平面、棱边和尺寸的物体为目标。优先保证一个具体物体的制作流程完整、可解释、可恢复，再扩展物体类别。

产品应同时说明三种事实：

- 哪些形状来自扫描观测。
- 哪些形状来自结构拟合或用户实测约束。
- 哪些区域来自推断，缺少实物观测。

外观清晰、几何光滑和尺寸准确是不同指标，不能互相替代。

### 1.2 系统分工

| 系统 | 负责 | 边界 |
| --- | --- | --- |
| OMNI 手持端 | SLAM、传感器时间关联、候选图片选取、原始素材保存、最终点云和附件交付 | Orange Pi 5 Max / RK3588 / 8 GB；不承担制作台重建、贴图烘焙或最终资产渲染 |
| Point View 本机软件 | 导入、提取物体、编辑、结构拟合、原图贴图、质量检查、工程保存与 GLB 导出 | 本路线的主要产品载体 |
| Blender 等外部工具 | 接收 GLB，进行进一步美术、网格、材质和场景编辑 | 不要求把完整 Blender 嵌入制作台 |
| 3DGS 空间留存 | 由其他同事负责 | 不纳入本路线的开发和验收范围 |

### 1.3 暂不承诺

- 单张照片恢复所有隐藏结构、真实厚度和精确尺寸。
- 所有类别物体全自动成形和贴图。
- 透明、镜面、强反光物体的可靠重建。
- 仅凭哈希、闭合网格或观感证明空间对齐与测量精度。
- GLB 自身保存制作台全部参数、原始素材与撤销历史。

## 2. 希望达到的产品形态

### 2.1 主流程

```text
导入扫描素材
  → 核对素材完整性与坐标状态
  → 选取一件物体
  → 确认方向、结构和尺寸
  → 按面关联原图并检查投影
  → 对照扫描检查还原度
  → 保存制作工程
  → 导出带纹理 GLB
```

制作台以大预览区为中心，侧栏按当前制作阶段显示必要操作。保留随时对照扫描原貌、撤销和返回上一步的能力。

### 2.2 三类交付物

| 交付物 | 用途 | 必需内容 |
| --- | --- | --- |
| 采集包 | 从 OMNI 接收素材 | 唯一最终 PCD、原始压缩图片、清单、标定、时间戳、相机位姿及坐标声明 |
| 制作工程 `.pvobject` | 本机继续制作、跨电脑恢复 | 局部点云、来源索引、原图、标定、变换、结构参数、面与图片关系、当前网格和制作状态 |
| GLB | 资产使用与外部编辑 | 米制模型、正确轴向、网格、UV、纹理、材质、必要部件命名及来源摘要 |

制作工程当前已有基础实现，但结构参数、按面贴图和完整操作历史仍待扩展。原始全量 PCD是否作为外部引用或可选打包项，应显式表达，不让用户误以为工程内一定包含完整扫描。

## 3. 当前源码状态

以下是本机静态审查结论，不等同于当前 AppImage 或 OMNI 实际运行状态。

| 能力 | 当前情况 | 判断 |
| --- | --- | --- |
| 点云选物、增减选区、局部原点 | 已有源码 | 可复用 |
| BPA / Poisson 表面生成 | 已有本地重建调用链 | 属于通用表面连接，不是箱体结构拟合 |

| 自动草稿、退出保护、制作工程 | 已有新增源码 | 新流程需独立运行验证 |
| 扫描与输出包围尺寸 | 已分别展示 | 不等同于物体自身长宽高或实测约束 |
| 箱体、平面、正交关系和尺寸拟合 | 尚未接入 | 核心待开发能力 |
| 按面原图投影、UV、纹理图集 | 尚未接入 | 核心待开发能力 |

旧图片保存和 COLMAP 导出分支不能直接等同于新附件输出：图片是否去畸变、位姿变换方向、单位、时间和最终点云关联都需要适配。

## 4. 功能清单

### 4.1 素材接收与管理

- 导入单独 PCD，并保留原有点云制作能力。
- 导入完整采集包，检查清单版本、路径、文件大小、哈希和图片解码尺寸。
- 明确区分“文件关联已核对”“沿用工程来源记录”“空间对齐未验证”。
- 显示缺失图片、错误标定、坐标不匹配等具体原因。
- 全部校验成功后替换素材，失败时保留已有作品。
- 以内容哈希共享同一批原图，避免每个物体、草稿和收藏重复存储。
- 提供本机素材容量、引用数量和显式清理入口；不得静默删除仍被工程引用的素材。
- 重新打开工程后，可以定位或重新关联原始 PCD，不能仅凭文件名认定同一来源。

### 4.2 物体提取

- 框选添加、框选减去、撤销选区操作。
- 按空间范围去除背景；后续可增加连通区域辅助选择。
- 保留原始点号，明确采样与完整数据的区别。
- 选区确认后保留返回调整的路径。
- 选区内混入地面、墙面或邻近物体时，提供可理解的检查提示。
- 语义分割可作为后续辅助候选，用户必须能修正选区。

### 4.3 结构与尺寸

- 第一类结构：箱体及其平面、棱边、长宽高。
- 提供物体自身坐标轴，支持确认或调整朝向。
- 分别保存扫描估计尺寸、用户实测约束与最终模型尺寸。
- 平面拟合、正交关系和尺寸约束的结果应可调整、接受和撤销。
- 原始扫描始终保留；结构候选不覆盖原始观测。
- 对凹陷、破损、胶带凸起等细节，允许选择保留或简化。
- 缺失背面、底面等区域明确标记，不自动归类为实测几何。
- BPA / Poisson 保留为自由曲面方式；高级参数默认折叠。

### 4.4 原图贴图

- 点击物体某一面，查看适合该面的候选原图。
- 候选排序综合可见面积、入射角、清晰度、曝光和像素覆盖。
- 显示图片到几何表面的投影叠加，支持人工核对。
- 检查遮挡、背面和视野外区域，避免纹理穿透。
- 区分原始畸变图与去畸变图，各自使用匹配的相机模型。
- 支持局部调整照片与结构面的对应关系；记录人工调整。
- 生成 UV 和纹理图集，处理接缝、曝光差与纹理边缘。
- 缺少照片的面可保留扫描顶点色或中性材质，明确未覆盖。
- 同一正面照片不得被自动拉伸到所有面并声称完整还原。

### 4.5 编辑体验

- 支持扫描点、结构候选、最终网格和贴图覆盖的切换对照。
- 以尺寸、面和图片为主要操作对象，整体美术材质作为次级外观选项。
- 重建和贴图任务显示阶段、失败原因与取消入口。
- 对长任务设置资源预算；避免影响基本交互。
- 自动草稿与明确保存并存，保存失败时保留当前编辑。
- 返回空间、重新选取、打开其他作品和关闭窗口采用一致的状态保护。
- 切换物体后，原图、原点、来源索引和坐标变换不得串用。

### 4.6 检查与交付

- 检查网格偏离观测点的程度，并区分已观测区域与推断区域。
- 检查最终尺寸、单位和物体朝向。
- 检查主要面的纹理覆盖、文字清晰度和接缝。
- 检查悬浮碎片、非预期开口、错误连接和法线。
- 导出普通 GLB 与纹理 GLB 时准确表达实际内容。
- 制作工程保留重新编辑资料；GLB 是交付结果，不作为唯一源工程。
- 在外部工具中核对尺度、轴向、贴图引用、材质和部件名称。

## 5. 数据和坐标契约

### 5.1 采集包至少需要

- 唯一 PCD 的文件名与 SHA-256。
- 每张原始压缩图片的相对路径、SHA-256、尺寸和采集时间戳。
- 相机模型、内参、畸变、外参及其版本。
- 明确的相机光学坐标约定和位姿方向。
- 位姿所在坐标空间：原始 SLAM 或最终 PCD 导出空间。
- 同次导出快照的身份和坐标修正来源。
- 同步偏差、筛选原因及预算统计。

纳秒时间戳在 JSON 中使用字符串；矩阵明确行列主序；四元数明确 `xyzw` 顺序。

### 5.2 投影链路

没有局部编辑时，先由物体局部点加回原点，得到点云导出坐标中的位置；再使用同一坐标空间中的相机位姿逆变换，得到相机坐标，最后通过匹配的相机模型投影到图片。

必须单独处理：

1. 原始 SLAM 位姿与最终 PCD 之间的关系。闭环修正可能随时间变化，不能默认一个全局刚体变换能解决全部帧。
2. 提取前的局部编辑。部分点移动不等于整件物体统一移动，应保留编辑作用的原文件点号和顺序。
3. 物体原点、单位及 GLB 的 Z-up → Y-up 导出变换。图像投影与最终展示变换不能重复应用。
4. 观测空间与展示空间的区别。模型展示时缩放，不应悄悄改变用于投影的物理尺度。

### 5.3 当前需要优先修正的契约问题

| 问题 | 触发条件与影响 | 建议 |
| --- | --- | --- |
| 编辑索引空间不统一 | 采样场景的编辑在 worker 中映射至原点号执行，但保存的 `sourceEdits` 仍是原采样索引；后续恢复投影可能找错点 | 将持久化编辑统一成原文件点号，显式标记索引空间 |
| 米制附件与手动单位冲突 | 附件声明米制，制作台仍允许切换厘米或毫米 | 区分来源单位和展示缩放；存在米制证据时阻止无说明的冲突修改 |
| 文件绑定不能证明几何一致 | 清单声明 `pcd_export` 不代表位姿已经正确转换 | 保存同次快照信息并做投影核验；验证前保持未对齐状态 |
| 恢复工程不含整份 PCD | 只能重新校验图片及工程数据，无法重新计算原始 PCD 哈希 | 保留来源记录状态，提供重新关联原文件的路径 |

## 6. 分阶段路线图

阶段以交付结果和验收条件划分，暂不承诺日历工期。每个阶段评审后再确定下一阶段范围。

### M0：本机数据与恢复逻辑收敛

**目标：让现有制作台能够可信地保存和恢复当前素材与编辑状态。**

工作项：统一编辑索引、明确单位契约、复核草稿和工程恢复、设计原图共享与总容量管理、补齐错误状态表达。

验收条件：

- 工程往返后局部点云、图片字节、标定、纳秒时间戳和来源索引一致。
- 错配图片、坏工程和保存失败不替换或丢失当前作品。
- 退出、重新选取、切换作品和重开草稿的行为一致。
- 原图未对齐状态不会被收藏或工程恢复升级为已验证。

此阶段不依赖 OMNI 上线，也不证明实机采集可用。

### M1：纸箱结构制作闭环

**目标：从本地点云生成可调整、受观测约束的箱体候选。**

工作项：物体朝向、平面拟合、正交约束、尺寸编辑、原始扫描对照、推断面标记、结构参数持久化。

验收条件：旋转摆放的箱体使用自身长宽高；约束修改可撤销；缺面不会被标成实测；输出尺寸与已接受约束一致。

### M2：本机单面贴图闭环

**目标：先让纸箱一个已观测面获得正确、清晰的原图纹理。**

工作项：相机投影、畸变处理、遮挡检查、面与图片绑定、UV、纹理导出。

验收条件：选用坐标已知的离线样例核对投影；文字朝向正确；背面不穿透；GLB 在外部工具中能显示纹理。真实纸箱精度仍需真实素材复核。

### M3：多面纹理与资产交付

**目标：把单面能力扩展为可检查、可恢复的完整物体制作。**

工作项：多图择优、按面覆盖、接缝与曝光处理、未知面管理、制作工程恢复、完整纹理 GLB。

验收条件：主要面的覆盖可检查；遗漏面明确提示；换图不破坏其他面；重新打开工程可继续调整。

### M4：OMNI 在线素材适配与实机验收

**目标：使真实采集链路稳定地产生制作台所需素材。**

工作项：相机原始字节接入、时间匹配、相机位姿转换、位姿驱动筛选、有界写队列、最终导出快照、清单发布及显式白名单同步。

验收条件：

- 静止与轻微移动不持续累计重复图片；更优图片替换行为可追溯。
- 匀速平移仍能保留新视角，不因低加速度被误拒。
- 写失败、空间不足和队列拥塞不会发布完整交付标志。
- 图片采集不会明显破坏 SLAM 的时间稳定性；阈值依据实测制定。
- 真实图片与最终 PCD 可投影核对，坐标修正来源明确。
- 同步完整性与恢复行为经过实机验证。

此阶段必须在本地方案、源码 review 和相应本机验证后，另行确认具体远程操作范围。当前不放行。

### M5：规模与类别扩展

在纸箱流程稳定后，再考虑圆柱、组合部件、自由曲面修整、辅助语义分割、批量资产制作和更大素材预算。每一类都应有独立样例和质量要求。

## 7. 关键问题与难点

### 7.1 时间同步与相机位姿

图片时间戳必须对应曝光和实际相机位姿。运动时的时间误差会转化为空间错位；传感器回调到达时间不能替代采集时间。需要明确曝光时间、位姿插值、IMU 窗口及时间偏差来源。

### 7.2 IMU 筛选只是调度辅助

现有近似模型根据归一化三轴动态加速度与角速度合成运动量，以反比例形式调节局部质量探测间隔。新位姿主要由几何变化触发。

去重力、去偏置的加速度来源仍需在线适配。阈值不能仅按理论值认定有效；振动、漂移、曝光和运动模糊都需要真实数据验证。空间方向桶表示相机观察分布，不等同于某个物体各面的纹理覆盖。

### 7.3 结构规则与实物缺陷的取舍

箱体平面化能压制扫描噪声，也可能抹掉真实凹陷。应让结构规则形成可比较候选，并依据观测残差与用户意图决定是否接受，而不是全局强制平滑。

### 7.4 照片细节与几何分辨率

清晰纹理不要求无限增加三角面数。应分别控制几何复杂度和纹理分辨率，依据近距离查看需求决定文字与标签的像素预算。

### 7.5 遮挡、接缝和外观一致性

照片包含真实照明与阴影，直接作为颜色纹理后可能与渲染光照叠加。需要区分外观留存与可重新打光材质；初期优先可解释的外观还原，不承诺自动恢复物理材质参数。

### 7.6 存储、内存和响应时间

压缩图片体积不等于解码内存。哈希、图片解码、工程打包和网格处理都可能产生额外副本。应限制并发，记录峰值内存；大图片采用按需预览，避免把全部原图同时解码。

当前单附件有数量和字节限制，但本机作品库仍需总容量管理。导出工程上限不能替代运行时内存预算。

### 7.7 质量标准如何设定

不要先写一个缺少依据的“毫米级”或固定帧率承诺。应使用实际纸箱样例、人工测量基准和固定显示条件，建立尺寸误差、投影误差、覆盖率、处理耗时及内存记录，再确定产品阈值。

## 8. 其他产品与工程问题

- **版本兼容：** 工程和采集清单需要版本迁移策略，旧工程不能被新字段静默误解释。
- **来源可追溯：** 记录算法版本、关键参数、用户约束和人工贴图调整。
- **撤销粒度：** 区分选区编辑、结构调整、换图和材质操作；恢复工程后是否恢复撤销历史必须明确。
- **任务失败：** 取消或失败应保留上一份可用网格和纹理，不覆盖为半成品。
- **导出一致性：** PLY、GLB 和工程应明确各自坐标与单位，避免同一物体出现不同尺度解释。
- **对象身份：** 改名、复制作品和导入工程的 ID 行为要明确，避免意外覆盖收藏。
- **素材权限与隐私：** 默认本机处理；照片可能包含室内和文字信息，未来任何上传能力需显式说明。
- **许可与分发：** 引入新算法、模型权重或运行时前核对许可证、分发条件和安装成本。
- **文案准确性：** “文件已核对”“空间已核验”“模型已导出”分别表达，不能混为“还原成功”。
- **维护边界：** 采集附件契约由采集端和制作台共同维护；3DGS 团队可共享必要素材规范，但不扩大本制作台范围。

## 9. 验证与放行原则

| 层级 | 能证明 | 不能证明 |
| --- | --- | --- |
| 静态源码 review | 数据流、接口和状态逻辑是否自洽 | 实际运行成功、图片质量、真实空间对齐 |
| 本机合成样例验证 | 数值变换、契约、恢复和错误处理 | 真实传感器同步与实物还原度 |
| 本机真实素材验证 | 特定样例的尺寸、投影与外观表现 | OMNI 长时间在线资源稳定性 |
| OMNI 实机验证 | 在线采集、写盘、同步和资源行为 | 任意物体类别都适用 |
| 打包应用验收 | 交付版本确实包含并运行相关功能 | 未覆盖硬件和样例的表现 |

验证执行按用户授权与阶段范围进行。旧构建和旧测试结果不为新源码背书。清单最后发布用于表示文件集合完成；它本身不是空间对齐证明，也不自动代表断电持久性保证。

## 10. 当前决策与待确认项

已明确：

- 主线是提取物体、编辑和 GLB 资产交付。
- 先本机方案、实现与 review；OMNI 图片链路未验证，不放行。
- 保留原始压缩图片、成功落盘后更新保存基准、容量限制、哈希绑定、最后发布清单和原始/导出位姿区分。
- 优先纸箱结构与照片贴图，不将 3DGS 空间重建并入本轮。

后续进入对应阶段前需要确定：

- 第一批真实样例及尺寸、外观验收要求。
- 人工实测尺寸是否必需，扫描估计与人工输入冲突时如何处理。
- 未观察面默认保持未知，还是允许用户主动接受结构推断。
- 最大单物体点数、图片预算、纹理分辨率及可接受处理时间。
- 工程是否可选携带完整原始 PCD，以及素材共享和显式清理方式。
