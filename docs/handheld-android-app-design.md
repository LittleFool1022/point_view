# 手持扫描设备 Android App 设计

日期：2026-09-09。版本：评审稿 v0.2。交付范围：页面交互和架构设计方案；未修改应用源码，未实现 Tauri 迁移，未进行 APK 构建或设备验证。

## 1. 目标与依据

面向手持扫描设备操作人员，以“连接设备 → 实时预览 → 扫描 → 检查 → 保存记录”为核心闭环。Android 优先，React 前端和数据处理复用于桌面端，应用壳采用 Tauri 2，设备实时数据通过 Foxglove WebSocket 接入。

视觉参考：[Kimi 扫描助手原型](https://jo4dk4aapy2yc.ok.kimi.link)。已读取页面 HTML/CSS 和交互脚本，未进行浏览器视觉验收。原型真实底部导航为“素材／中央扫描入口／记录”，设置由记录页进入。保留该结构及浅色青绿方向。

功能与作业流程对标：[Q9000 用户手册 CN V1.3.4](/home/jn/Downloads/Q9000用户手册_CN_V1.3.4.pdf)。已提取全册 31 个 PDF 页文本，并查看印刷页 14、19、22 的页面图像；以下页码均为印刷页码，PDF 阅读器页序为该页码加 2。手册描述的是 Q9000，不能作为本设备已有相同能力的证据；初始化时长、运动阈值、精度和配件要求不得直接复制为本设备参数。

方案主张：沿用原型的轻量移动界面，采用 Q9000 的设备端作业闭环和项目管理方式，用现有点云/CAD 能力补足手机端成果查看。三个主入口保留，专业工具逐层展开。

当前代码依据：

- `package.json`：React 19、Three.js、Foxglove 协议库；应用壳目前为 Electron 和 Capacitor。
- `src/transport/foxgloveSource.ts`：Foxglove 连接、ROS 消息解码、Worker 分流、按当前相机订阅。
- `src/components/PointCloudCanvas.tsx`、`CameraView.tsx`：现有点云和相机视图复用候选，移动端适配仍需实现阶段核查。
- `src/platform/files.ts`：依赖 Capacitor 和桌面桥；Tauri 迁移需替换文件访问及平台判定。
- `README.md`：设备端提供 ROS、同步与三目着色；当前应用消费显示数据。正式三目名称为前／左／右，原型前／中／后不能直接沿用。

## 2. 页面与信息架构

| 页面 | 主要内容 | 主要动作与状态 |
| --- | --- | --- |
| 素材 | 素材与教程两个页签，真实资源缩略图、名称和来源 | 查看、下载、学习；无资源时显示空状态。交易和账户接口未确定，不伪装购买成功 |
| 扫描入口／设备连接 | 最近设备、连接进度、设备身份、实时数据就绪情况 | 连接／重试／进入预览。区分网络已连接、服务已连接、数据已到达 |
| 扫描准备 | 项目名称、当前设备、场景模式、设备可用容量、相机与同步状态 | 静置提示 → 开始初始化 → 等待设备允许移动。传感器参数需能力查询和回执 |
| 全屏扫描 | 点云／图像主视图、可切换画中画、计时、轨迹、数据状态 | 默认开始／结束；暂停仅在设备声明支持时出现；工具用侧边面板或底部抽屉 |

| 记录详情 | 点云预览、元数据、文件、校验结果、标注与传输状态 | 测量、剖面、切片、DXF 导出；补扫、上传按能力开放 |

默认进入扫描入口；恢复上次未结束会话时先查询设备状态。素材和记录采用竖屏，扫描横屏优先并保留竖屏可用布局。设置入口沿用记录页右上角，扫描中提供当前任务相关设置。项目列表、点云查看和测量在无设备连接时仍可使用已完整下载的本地数据。

## 3. 核心扫描布局

横屏主视图占据全部可用内容区，常用操作分布在边缘，减少遮挡被扫描对象。

```text
顶部：返回    设备／连接状态    同步状态    设备电量／存储
主体：点云或图像；左上可折叠画中画；一条可执行的异常提示
右侧：计时／扫描状态    开始／结束按钮    拍照或标注入口
底部：显示模式    前／左／右相机    视角复位    更多设置
```

这是对原型底部居中快门的调整：横屏时放在右侧拇指区，竖屏时放回底部中央，也与 Q9000 印刷页 14 的横屏主操作位置一致。扫描过程隐藏主导航；返回键优先关闭面板，再处理退出扫描。设备支持暂停时，暂停作为独立次按钮出现，避免将同一个图标同时解释成暂停和结束。

- 点云与图像均使用真实数据；没有首帧时显示等待状态，不能用装饰点阵表示实时扫描。
- 预览切换不改变正在记录的内容。设备录制与手机预览订阅必须独立。
- 移动过快、距离过近等提示需要实际测量和经过确定的阈值；条件不具备时不显示虚假建议。
- 电量明确是设备电量；容量明确是设备还是手机。未知值显示“暂无数据”。
- 数据过期后显示“画面已停止更新”和最近接收时间，不能继续呈现“实时正常”。
- 实时状态更新不重建画布、不重置用户视角；相机切换期间显示加载状态。

## 4. 视觉与交互规范

风格依据：现场工具需要迅速识别状态，因此采用低动效、规则对齐、中等信息密度；沿用原型浅色底和青绿强调，扫描时让真实画面成为视觉主体。主要动作使用实心按钮，状态同时使用图标和文字。

| Token | 建议值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#F3F5F8` | 素材、记录、设置 |
| 内容表面 | `#FFFFFF` | 卡片和表单 |
| 主文字 | `#1C2430` | 标题、正文 |
| 次文字 | `#596575` | 辅助信息 |
| 主强调 | `#0F766E` | 主按钮、选中标记；比原型主色加深 |
| 选中背景 | `#E2F1EE` | 页签选中底色，配合字重和指示条 |
| 警告／错误 | `#92400E`／`#B91C1C` | 浅色背景上的状态文字 |
| 扫描控件底色 | `#20272D` | 关键状态标签和按钮，白色文字 |
| 分隔线 | `#DCE2E8` | 非交互分组边界 |

采用现有 CSS 变量和 Lucide 图标体系，不为设计引入 Tailwind。字号建议标题 20–24、正文 16、辅助信息 14 CSS px；计时使用等宽数字。页面边距 16、组间距 24、组件间距 8–12、圆角 12–16 CSS px。

触控区设计目标至少 48 × 48 CSS px，主扫描按钮 72 × 72；真机阶段核查 WebView 缩放与实际触控尺寸。使用系统字体、支持字体放大、刘海与底部手势安全区，不能复制原型固定手机外壳尺寸。

组件状态：默认／按下／键盘焦点／禁用／加载／成功／失败，桌面补充悬停。按钮请求中禁止重复提交但保留进度说明；错误在对应动作附近显示并提供重试。焦点使用清晰描边，状态不能仅靠颜色区分。正文对比度设计目标至少 4.5:1，实际界面需另行验收。

面板开合 180–220ms，按钮反馈约 100ms；遵循减少动态效果偏好。没有滚动入场、背景粒子或持续呼吸动画。缩略图来自真实扫描截图或实际教程封面；无缩略图采用文件类型图标和说明。

## 5. 会话状态与结果真实性

连接状态与扫描会话分别管理，避免断网被误认为已经停止设备扫描。

```text
连接：未连接 → 连接中 → 等待数据 → 可预览
                         ↘ 超时／断开 → 重连 → 查询会话

会话：准备 → 静置初始化 → 扫描中 → 确认结束 → 正在结束
                                                    ↓
                                                设备保存中
                                                    ↓
                                                  已保存
可选分支：扫描中 → 正在暂停 → 已暂停 → 正在恢复 → 扫描中
任一命令无明确结果 → 状态待确认 → 查询设备权威状态
```

- 点击开始只进入初始化等待；命令已接收不等于初始化完成，收到设备会话的运行状态后才显示“扫描中”。失败显示设备原因、重新放置提示和重试入口，不使用固定倒计时自动判定成功。
- 暂停不等于停止相机预览；Q9000 手册主流程未说明暂停，故本方案不将原型的暂停功能视为基础能力。仅在设备明确支持并定义语义后开启。
- 完成后等待文件落盘及清单返回；写入失败保留会话和重试入口，不显示保存成功。
- 断线保留会话 ID、已确认状态和本地成果，提示“设备扫描状态待确认”；重连后查询，不盲目重发开始命令。
- 扫描中返回或按系统返回键，显示“继续扫描”和“结束并保存”两个选择。若设备已验证支持后台独立采集，可另提供“仅离开预览，设备继续扫描”，并持续显示活动会话入口。未成功保存前不可清空数据。
- 补扫只能在设备支持原会话恢复或明确配准流程时开放，不能仅相加帧数就称为合并成功。
- 后台／锁屏后客户端可能停止预览；设备端采集是否持续取决于设备会话。返回前台必须重新查询。

## 6. Foxglove + Tauri 2 + React 架构

```text
React / TypeScript
  ├─ 页面：素材、连接、扫描、记录、设置
  ├─ 应用状态：连接、会话、项目副本、传输任务、显示偏好
  ├─ FoxgloveSource → 解码 Worker → Three.js / 图像视图
  └─ 平台适配接口
       └─ Tauri 2：文件访问、生命周期、原生能力
            └─ Android 必要插件：系统网络交互、文档访问等

手持设备
  ├─ 现有 ROS / 算法 / 相机 / 同步 → Foxglove Bridge → 实时预览
  └─ 待核实的采集控制与文件服务 → 会话控制、落盘、下载
```

Foxglove 在这里指数据协议与客户端接入层；手机界面由 React 构建。现有浏览器 WebSocket 数据链优先复用，不默认把每一帧大数据经 Tauri JSON IPC 往返转发。是否需要原生网络或录制路径应由后续真机性能证据决定。

Tauri 2 支持移动端、桌面端和 Web 前端框架，原生能力可通过 Rust 和移动插件接入。来源：[Tauri 官方介绍](https://v2.tauri.app/start/)。这些框架能力不意味着设备 Wi-Fi 自动连接、锁屏录制和大文件保存已自动具备。

预览沿用设备当前 topic 契约：三目精确点云 `/cloud_registered/tri_precise`、里程计 `/aft_mapped_to_init`、前／左／右压缩图像以及 `/omni/sync/status`。具体配置保留可编辑能力。

控制协议先核实设备现有服务；若 Foxglove 服务能力能满足要求，优先复用，否则再确定独立控制服务。设计所需的最小语义为：查询设备能力、查询当前会话、初始化／开始／结束、查询文件清单及结果；暂停／恢复作为可选能力。接口需要会话 ID、命令 ID、确认结果和可追踪错误；这里不是已存在的 API 定义。

## 7. 保存与性能边界

- 建议设备保存完整采集数据，手机按需预览和下载。手机收到的抽样点云不等于完整原始数据。
- 当前应用本地 MCAP 录制属于显示链路录制，不能直接代替设备三目全量采集。
- 记录必须标识设备端／手机本地／云端各副本状态；元数据保存与数据文件落盘分别确认。
- 大文件采用流式或分块原生写入设计，避免完整文件转 Base64 后跨桥复制。
- 保留现有 Worker 解码思路、单路相机预览和点数预算。预览允许丢弃积压旧帧；完整录制链路不能静默丢帧。
- 所有性能预算都是待测目标，不在设计阶段承诺点数、帧率、续航或设备兼容性。

连接失败保留设备选择和项目名称。RTK 不存在时显示“未安装”，不能将非必需配件当作基础扫描故障。初始化必需传感器由设备能力决定。模式首先承载操作指引；只有设备确认支持，才下发相应采集参数。

### B. 结束扫描／保存

```text
结束扫描？
设备将停止采集并保存本次项目。
[继续扫描]                 [结束并保存]

设备正在保存项目
当前阶段：…       进度：有依据才显示
请保持设备供电；当前会话：…

项目已保存到设备
项目：…    文件：…    总大小：…
[查看项目]                 [下载到手机]
```

完成操作前可继续原扫描；设备已结束后“补扫”属于新段关联或会话恢复能力，不复用“继续”文案。保存阶段断线时显示“保存结果待确认”，查询成功后恢复结果页。校验摘要分开呈现文件完整性、图像/位姿对应情况、空间覆盖评估；其中一项成功不能代替其他项。

### C. 记录／项目副本

```text
扫描记录                           设置
[手机本地] [设备项目]              传输
```

### D. 本地项目／测量／切片

```text
返回       项目名称            文件/分享
┌─────────────────────────────────┐
│                                 │
│         可旋转的点云主视图         │
│         测点与尺寸随几何显示        │
│                                 │
└─────────────────────────────────┘
[显示] [测量] [剖面] [切片] [标注]
展开面板：当前步骤、参数、撤销、确认
```

- 普通查看：单指旋转，双指平移／缩放；选点工具开启后，单指点击选点，拖动仍可调整视角。选中模式常驻显示名称和退出按钮。
- 距离：选择 A → 选择 B → 显示空间距离；水平距离与高差另行标注，不混为一个结果。
- 面积：依次选点 → 闭合 → 显示结果，明确投影平面和单位；非平面点集提示采用投影面积，提供撤销末点。
- 剖面：选 A/B 确定方向和长度 → 第三点确定厚度，另提供数值输入 → 生成剖面 → 在剖面内测量。与手册第 22 页的选点流程对应。
- 水平切片：俯视预览 → 调整中心高度 h 和厚度 t → 查看保留点 → 导出 DXF。设计定义保留范围为 `[h-t/2, h+t/2]`，单位可切换但内部保持米。
- DXF 导出前明确导出的是切片点、人工线还是拟合线；拟合/补齐结果保留来源标记。尺寸结果不自动代表设备标称精度。
- 手机工具默认展示轻量操作；复杂线稿整理可在桌面继续，但同一项目的标注与坐标信息需要随文件携带。

### E. 下载与上传

```text
项目传输：…
阶段 1  设备 → 手机       下载中 / 已完成
阶段 2  手机 → 云端       等待网络 / 上传中 / 已完成
当前阶段进度 …     已传输 … / 总大小 …
[暂停任务] [重试] [返回项目]
```

“一键上云”编排两个可恢复任务。先确认本地副本完整，再引导接入互联网；用户允许使用移动数据后才按对应策略上传。设备热点无互联网不能显示为设备连接失败，也不自动切断活动扫描的设备连接。进度按字节计算，云端接收成功与训练完成分别显示。账号、上传和训练服务尚未提供时，保持设备下载与本地导出可用。

### F. RTK／控制点／配件标注

RTK 面板显示接收机连接、Ntrip 连接、解状态三个独立字段；Ntrip 已连接不能替代固定解。卫星数、差分龄期、PDOP、HRMS 仅在设备提供时显示，并带更新时间。保存配置前检查必填字段；服务凭据不出现在诊断导出中。手机粗略位置仅用于项目地点索引，不替代测量坐标。

控制点流程为“编号 → 对准实体参考点 → 按设备要求静置 → 采集回执 → 保存坐标与质量 → 复核列表”。已知地面坐标与扫描系观测坐标分字段存储，记录坐标系、单位、时间和参考点外参。手册的底部观察孔和静止 3 秒是 Q9000 硬件流程，本设备应另行定义。

照片与全景流程为“拍摄请求 → 设备完成 → 预览 → 保留/重拍 → 添加文字或附件”。记录照片 ID、位姿/时间及空间关联依据；没有标定投影不能声称实现 AR 测点。森林模式复用切片视图，树种标签和位置持久保存到项目，不仅保留在屏幕上。

## 9. 架构契约与迁移范围

### 9.1 四个边界

| 边界 | 职责 | 不承担的内容 |
| --- | --- | --- |
| React 页面与领域状态 | 流程、交互、项目索引、测量/标注、任务状态 | 不以页面计时器代表设备会话 |
| Foxglove 数据层 | 接收点云、图像、位姿、可用遥测，消息解码和订阅 | 不默认负责 Wi-Fi 接入、文件下载或设备全量录制 |
| Tauri 原生适配 | 原生文件、应用生命周期、系统网络入口、需要时的传输任务 | 不在手机启动 ROS/SLAM，不默认经 JSON IPC 搬运逐帧点云 |
| 设备服务 | 初始化、采集会话、传感器、落盘、项目文件与权威状态 | 不依赖 React 页面持续存活 |

建议的领域对象：`DeviceCapabilities`、`ScanSession`、`ProjectManifest`、`ProjectReplica`、`TransferTask`、`SpatialAnnotation`。名称为设计建议，未创建代码或新增全局依赖。

- `DeviceCapabilities`：设备身份、协议版本、必需传感器、可选配件、支持的操作。
- `ScanSession`：设备 ID、会话 ID、运行阶段、控制拥有者、最后确认时间、设备错误与结果项目 ID。启动响应丢失时按命令 ID 查状态。
- `ProjectManifest`：稳定项目 ID、版本、坐标系、单位、文件清单、采集时间、设备身份。编辑信息与原始点云分离。
- `ProjectReplica`：设备/本地/云端位置、版本、文件完整性和可用性；三个位置不是一个“已保存”布尔值。
- `TransferTask`：源/目标、项目版本、文件、已完成字节和重试状态；断点恢复仅在服务支持时开启。
- `SpatialAnnotation`：类型、项目/会话 ID、坐标系、位置、时间、文本与附件引用；控制点额外保留参考坐标。

设备控制可通过 Foxglove 可用的服务能力或独立控制接口承载，需依据现有设备协议选择。本轮不虚构 URL、ROS service 名或可调用方法。设备端至少要能回答“是谁、能做什么、当前在做什么、上个命令结果是什么、项目保存在哪里”。

若另一手机持有活动会话，显示“设备正在被使用”和会话状态，不自动抢占控制。多端接管规则和认证方式由设备协议确定；恢复使用本机保存的会话标识，不仅凭设备 IP 判断。

## 10. 交付边界与评审结论

本轮已形成页面结构、关键线框、操作状态、Q9000 对标矩阵、数据与控制边界、当前源码复用清单。设计保留 Kimi 的三入口和青绿视觉，以 Q9000 的初始化—设备扫描—设备保存为主流程，记录页补齐设备/手机副本与本地成果处理。

进入实现前需确定三项：目标 Android 手机/手持屏的尺寸与系统版本；设备初始化/扫描/保存控制协议；设备项目文件下载接口。它们影响具体实现，不阻塞本设计稿交付。云服务、RTK 和配件按能力逐项接入。

后续获授权后的最小验收场景：

1. 设备热点无互联网，仍可连接、收到首帧并展示真实身份。
2. 初始化未完成时不提示移动；失败可重试且不重复启动会话。
3. 扫描中断网、App 重开后查询恢复原会话，不能把预览断开当停止采集。
4. 结束命令重复点击、回执丢失或保存失败时，结果可确认且原会话可追踪。
5. 设备项目下载完整后才进入本地项目；删除本地副本不删除设备原件。
6. 剖面三点、切片厚度、距离/面积单位和 DXF 内容语义一致；原始点云保留。
7. 设备到手机、手机到云端的传输状态独立；断网和空间不足可恢复或明确重试。
8. Android 横竖屏、系统返回键、字体放大、安全区、图形性能和文件导出符合实际目标设备。

上述为验收定义，本轮未执行测试、构建或真机验证。
